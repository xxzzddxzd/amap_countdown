# AMap Signal Countdown

适用于高德地图 `com.autonavi.amap` 16.11.1 的 rootless 红绿灯倒计时插件，支持汽车和自行车导航。

## 1.1.0：多路口与本地历史

- 全屏上方三分之二显示主路口，下方三分之一左、右分别显示后续两个前方路口。每块区域按灯色显示背景和倒计时；数据不足时显示灰色等待。
- 向上滑切换到后一个前方路口，向下滑返回前一个仍在前方的路口。默认跟随最近路口；手动选中的路口通过、移除或被拉黑后恢复默认选择。
- “路口管理”保存路口名称、进入道路和该来向的黑名单。记录以信号灯 ID＋进入道路为键，分别保存各个来向的相位、时长和时间戳。拉黑只跳过对应来向，采集继续进行。
- 原生灯态优先；已确认来向且当前原生相位缺失时，可由 SQLite 中的历史周期推算灯色和剩余时间，并明确显示“预测”。预测数据不会反过来参与学习。

### 确认进入道路与黑名单

进入全屏后打开“路口管理”，填写可选的路口名称，以及必填的进入道路，例如“中山路北段”，保存即可开始按该来向记录。同一路口的不同入口应使用不同名称；之后可在历史列表中选择已保存的进入道路，或单独拉黑、恢复某个来向。先滑动到后续路口，也可以提前为它确认来向。

首版尚未验证高德提供的进入道路名称与稳定导航会话 ID，因此来向需要手动确认，不会根据唯一一条历史记录猜测入口。绑定仅在本次连续导航中保留；检测到导航状态、模式、路线偏移变化或应用进入后台时会清除绑定，数据库保留。开始新导航或重算路线后，请使用“重新确认来向”再选择进入道路；原生 ID 和偏移完全相同的重算目前无法自动区分。

### 数据与预测

数据库位于高德应用沙盒的 `Library/Application Support/AMapSignalCountdown/Signals.sqlite3`，完全在设备本地保存。未确认来向的路口仍可显示原生倒计时，但不会写入某个方向的历史或应用该方向的黑名单。

学习需要两个连续、时长一致的完整周期。既可读取原生完整相位表，也可记录实际变灯时刻；首次看到半段倒计时不会被当成完整红灯或绿灯时长。新的原生相位与模型冲突时立即停用旧预测，重新学习。重复快照不会延长模型有效期，模型超过六小时停止预测。预测用于当前路线中仍在前方且已确认来向的路口；原生位置或身份不可靠时等待，不用历史记录猜测路线。

## 功能

- 读取高德进程内已有的原生红绿灯状态和倒计时数据；汽车相位按原生绝对时间连续推进，使用灯组当前状态 `+0x38`，不以后续相位状态 `+0x28` 拒绝刷新。
- 汽车记录和相位缓存必须匹配当前路口 ID；不再把 `flag=1` 当作当前路口，也不使用单条记录或陈旧同步 ID 猜测选灯。无 ID 的 `status + remainTime` 只记录日志，不覆盖显示；汽车秒数支持 0–999。
- 取数兜底只读汽车距离筛选前的原始输入：仅选最近且唯一的前方 signal，原始相位有效才显示“原始取数”；此来源暂停速度、距离和预测显示，不修改定位、不跳过缺相位路口去显示更远的灯。
- 以可拖动悬浮球显示灯色、灯名、剩余秒数和到当前路口的原生沿路线距离，松手后自动贴靠屏幕左侧或右侧。
- 单击悬浮球进入全屏倒计时，双击全屏退出；非原始取数来源下，全屏单独显示当前速度或高德原生五点平均速度。
- 主路口与高德当前路口匹配、且使用有效原生数据时，全屏根据当前速度、路口距离和未来多轮相位，以最小速度变化计算保持、缓慢提速、缓慢减速或准备停车建议；手动切到其他路口或使用历史预测时暂停建议。
- 全屏数字按最多三位数固定字号；两位数和一位数不会继续放大。
- 到 0 米仍视为当前路口；通过或原始目标移除后才切换。当前路口无法确认或没有有效相位时等待，不跳到后面的灯。
- 暂无有效数据时显示灰色等待状态；`tmp/amap-signal-countdown.log` 的 `car capture` 记录当前/后续灯态与拒绝原因，`countdown hidden` 记录变成 `--` 时的缓存时效和数据源原因。

## 边界

插件不使用 OCR、网络拦截、GPS、Core Location 或经纬度距离推算，也不进行视图树扫描或全进程内存扫描。路口距离来自高德导航引擎当前 route offset 与倒计时 signal route offset 的原生差值，速度来自活跃 travel route 状态，并由 TravelNaviInfo 原生消息交叉验证。建议受车型速度上限、有限加减速度、绿灯安全缓冲、近路口禁止提速和数据时效约束。

骑行引擎未发布 signal ID/相位时，插件不会把未匹配的机动车灯态冒充为骑行灯；如需汽车信号数据，必须保持高德汽车/巡航数据源运行。倒计时仅供参考，始终以现场交通信号灯、道路状况和交通规则为准。

## 编译与验证

需要支持 `arm64-apple-ios15.0` 的 Clang、iOS SDK、`ldid`、`dpkg-deb`，以及用于主机测试的 C 编译器和 SQLite 开发库。可通过 `CLANG`、`LDID`、`OTOOL`、`NM`、`HOST_CPPFLAGS`、`HOST_LIBS` 指定工具路径；构建过程链接 iOS 的 `libsqlite3`。

```sh
make test
make all package
```

产物为 `build/com.dsh.amapcycleassist_1.1.0_iphoneos-arm64.deb`。主机测试覆盖方向隔离、持久化黑名单、周期学习与漂移失效、多路口选择和经过移除、原生缓冲区解析。触摸手势、键盘、旋转及高德运行时取数需要在对应 iOS 设备上验证。

### 本地 USB 真机检测

若设备通过 USB 接在本地电脑，SSH 转发端口为 `2224`，请在该电脑运行检测脚本。云环境的 `127.0.0.1` 与本地电脑不同，无法直接使用这个转发端口。

```sh
bash tests/device_smoke.sh --target root@127.0.0.1 --port 2224
```

将 `root` 换成实际 SSH 用户名；SSH 登录和主机密钥验证沿用本地配置。脚本收集已安装版本、插件加载日志及 SQLite 状态，并把报告保存在本地。启动插件前先确认高德版本精确为 `16.11.1`，原生挂钩使用此版本的固定偏移。

真机操作顺序：安装 1.1.0 并重新打开高德，验证悬浮球和路口管理；在能取得多个前方信号灯的路线中验证三块显示、上下滑动及经过后移除；保存真实进入道路，拉黑再恢复该来向，并检查报告中的记录变化。重启后历史和黑名单应保留，来向需要重新确认。历史预测需要完整稳定周期和仍有效的前方位置；仅在界面实际出现“预测”并随后恢复“原生”时，才能确认该项真机测试通过。
